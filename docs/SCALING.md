# 模块生成、增量接口与性能验收

## 原型生成和加载

`server/demo-modules.ts` 按具体需求的业务模块分组，未分组的具体卡共同生成一个完整模块；导航沿用需求顺序。每个模块有独立输入摘要、源码、构建 HTML、需求映射和检查报告。输入包含本模块有效字段、相关概要的共同规则、参考原型配置和平台模拟状态契约。模型只读取本模块旧源码，以及上轮声明依赖的其他模块需求摘要。

需求与契约不变时，核对源码、HTML 和构建报告后复用模块。采用共享数据接口的工程，仅重建自身需求变化的模块；新增可选标量字段仅由平台追加类型成员，并核对编译后的运行逻辑完全相同，保持运行标识与未变化模块缓存。运行接口变化使全部模块失效，依赖移除仍会使引用模块失效。没有共享契约的旧工程继续保守地传递依赖失效。新增字段描述和页面补丁在同一次模型响应中返回，平台校验后合并；新实体、状态枚举或已有类型变更仍请求整体更新，不能私建第二套数据。优先调度当前沟通卡片所在模块，每个项目最多两个模块同时处理，全进程最多两个模块请求模型，等待队列最多 64 项、最多等待 10 分钟。

`buildPreview` 在无网络沙箱中执行编译、非空、页面打开和布局检查，成功后发布可操作版本；失败最多修复两轮。`verifyModularDemo` 后台先调用模型补充受影响的检查清单，再串行检查完整定位与交互，复用未改变的已通过报告；不重新生成代码。后台检查限一个容器任务，避免连续对话争抢浏览器资源。状态为 pending / passed / needs-attention / interrupted，按产物 ID 与源码摘要精确回填，重启恢复当前 pending 修订。有效需求变化会取消旧模型请求，普通消息数量不作为原型缓存依据。

后台检查清单使用 `checkUpdates` / `bindingUpdates` 按旧索引替换，未涉及条目保留；新增条目单列，禁止重复索引、越界或静默删除旧检查。数据定义不变时前端更新模块地址，保留导航、表单和模拟记录；数据定义变动时重建预览实例，避免旧数据套用新接口。

可信导航壳只请求当前模块。模块通过带 `sandbox="allow-scripts allow-forms"` 的独立 iframe 执行，不能访问工作台 Cookie、存储或网络；只有平台生成的导航壳使用同源 iframe。壳通过校验消息来源的 `postMessage` 提供最多 256000 JSON 字符的模拟状态，支持模块表单、记录、共享业务数据和模块导航。默认虚构员工契约统一为林晓 / E1001 / 行政部，需求明确其他身份时以需求为准。页面刷新、重置或发布新产物会清空模拟数据。

每个不可变产物使用 `/api/projects/:id/demo/artifacts/:artifactId/index.html`，核对产物属于项目历史后返回私有一年缓存与 ETag。界面只读取 `/demo/view?metadata=1` 的状态和地址。PRD、材料箱和放大预览切换保留同一个原型实例。ZIP 包含独立模块源码、离线 HTML、模块元数据、正式 PRD、`verification.json` 与 `build.mjs`；解压后可直接打开 `index.html`，或 `npm install && npm run build` 重建模块。

旧版整体原型仍可查看和导出；下一次生成时迁移为模块工程。更改模块名会改变模块标识并重新生成，跨模块关系需要模型声明依赖，不能仅凭页面同属一个项目就推断业务耦合。

## 增量数据与持久化

首次 `/api/workspace/sync?projectId=…` 返回 `snapshot`；携带 `cursor` 后返回 `unchanged` 或带 `base` 的 `delta`。补丁支持设置、删除字段和追加数组，客户端仅复制变化分支。游标按项目和当前参与身份隔离，进程缓存上限 24 MiB / 128 项；游标过期、被淘汰或服务重启后自动返回完整紧凑快照。超大快照不会进入缓存，客户端仍可正常读取。

紧凑快照包含材料元数据、每卡最近 4 条消息及当前建议引用/待处理变更等必要消息、最近 2 次卡片修订，以及评审版本元数据。消息总数和变更摘要独立保存，避免分页影响“建议是否过期”等判断。以下端点按需读取完整内容：

| 端点 | 用途 |
| --- | --- |
| `/api/projects/:id/cards/:cardId/messages?limit=40&before=…` | 按消息索引分页，最多 100 条 |
| `/api/projects/:id/cards/:cardId/history` | 单张卡片完整修订记录 |
| `/api/projects/:id/materials/:materialId/text` | 单份材料正文 |
| `/api/projects/:id/history` | 评审快照、交付与审计历史 |
| `/api/projects/:id/events` | SSE 变化通知，不携带正文 |

SSE 合并 100ms 内的变化，连接最多 128 个、15 秒心跳；浏览器保留每 3 秒的补查，断线不会丢更新。通知和游标缓存为单进程实现，当前部署保持一个应用实例。

PostgreSQL `workspace_heads/cards/messages/materials` 是事务内同步维护的读表；`workspace_cards.history` 单独保存完整卡片修订。首次启动自动为旧项目补齐这些结构。高频讨论使用 `discussion_appends` 和消息索引追加，不重写整个项目 JSONB。带 `baseRevision`、`baseRound` 和 `clientMessageId` 的独立发言，在同一卡片修订内允许并行追加；消息标识按参与人去重，重复标识不能更换内容。正文修订或确认轮次变化仍拒绝过期发言，正式领域修改仍校验项目版本戳。

`getProject` 在同一数据库快照中合并正式项目与讨论追加；后续领域修改在项目行锁事务内合并追加、写入正式 JSONB、清除已合并追加并更新读表。**备份必须包含整个数据库及 `data/`，不能只复制 `projects.body`**，因为未合并的讨论保存在追加表中。正式评审、交付与大规模材料抽取仍可能读取完整领域数据，本轮没有把全部业务写入改为细粒度关系模型。

## 耗时监测

所有普通 HTTP 响应提供 `Server-Timing: app;dur=…`。产品身份可查看 `GET /api/metrics`：归一化 API 路径的耗时、响应字节数、失败数，以及模型、模块排队/生成/构建/交互检查、整次原型任务和预览加载耗时。路径中的项目/卡片 ID 不作为指标标签，指标不保存材料、聊天、提示词或密钥。前端仅上报固定的 `preview.load` 耗时。

指标保存进程累计计数与最近 2048 个采样的 P50 / P95 / 最大值，重启后清空；原型修订和任务结果中的 `timings` 持久化保存。新修订的 `timings.totalMs` 为开始生成到可操作预览发布的墙钟耗时，`verification.durationMs` 记录随后后台完整检查的耗时；旧修订的 `totalMs` 包含完整检查，不应混作同一口径。并行模块的 `generationMs`、`buildMs`、`checkMs`、`queueMs` 为工作量之和，可能超过墙钟耗时。浏览器 `load` 反映文档载入，不代表所有业务交互都已人工验收。

## 讨论流式与结构恢复

需求监听、建议生成及原型模块生成均使用 Mastra `agent.stream()`。服务器持续读取响应，通常每 5 秒更新一次任务标签中的接收字数，并通过现有 SSE / 增量同步显示进度。流式改善等待反馈，完整 JSON 和业务证据仍在结束后校验，半成品不会写入正式需求或建议。

讨论建议的 `dependencies` 表示字段间的定向业务依赖，与原型的模块依赖 ID 列表不同。每条必须包含 `field`、`requires` 数组和具体 `reason`。传入模型完整 JSON Schema；校验前仅规范明确等价的表示，如中文字段名、单条依赖对象、`dependsOn` 别名和单个关联字段字符串。无效字段、自依赖、重复依赖及非本轮变更仍被拒绝，不会通过删除依赖来掩盖问题。

仅依赖结构错误时，先验证其余建议，再让模型只返回依赖元数据；字段正文、引用和问题解决结论保持原样，并再次完整校验。其他校验错误保留一次完整修复。建议输出省略重复的 `before`，由输入卡片精确补齐；显式传回不匹配原文仍拒绝，入库时继续校验修订与讨论是否变化。模型上下文排除旧 Agent 发言，保留真实人类讨论和材料。

建议输出预算为 12288 tokens；发生明确长度截断时，只精简重试一次，预算 16384 tokens；仍失败则保留原有内容，不接受截断 JSON。结构修复最多一次。DeepSeek V4 / Kimi K3 请求设置 `reasoning_effort=low`，避免较高默认思考量挤占输出预算；未知模型不附加该参数。DeepSeek 默认思考强度及可选值参见 [官方文档](https://api-docs.deepseek.com/guides/thinking_mode/)。

显式点击“重新分析”只为本次重试忽略已读游标，仍检查本期范围、已有确认时间和交付冻结；正常自动监听继续去重。后台等待模型期间若数据库空闲连接被关闭，连接池记录安全提示并允许后续重新连接，避免未处理的空闲连接事件使应用退出。

## 运行验证

需要本地 PostgreSQL、Node 24 和已准备的 `requirements-demo-runner:1` 镜像：

```sh
pnpm test
pnpm build
pnpm demo:verify
pnpm demo:verify-modules
pnpm load:test
pnpm load:test --sizes=1000 --duration=30 --writes=512 --report=.work/scaling/load-test-sustained.json
```

压测创建随机命名的临时数据库，运行本地真实 HTTP 服务，关闭付费模型和外部交付，结束时关闭连接并删除该数据库。数据库账号需要创建临时库的权限；可用 `TEST_DATABASE_URL` 单独指定测试实例。每张需求生成 100 条合成讨论，每 5 张卡生成一份长材料，按每 20 张卡划分一个原型模块。

默认测试 100 / 300 / 1000 张需求，20 个并发客户端持续读取 3 秒；随后 4 个写入者和最多 8 个增量读取者混合运行，检查消息不丢失、零版本冲突、补丁重建一致，以及修改一张卡只使一个模块失效。`--sizes`、`--concurrency`、`--requests`、`--duration`、`--writes`、`--report` 可调整。默认预算是首屏字节缩减至少 80%、无变化读取 P95 ≤200ms、写入和混合读取 P95 ≤1000ms；对应 `--max-read-p95-ms`、`--max-write-p95-ms`、`--max-mixed-p95-ms` 可设置预算，超过时命令失败。

`demo:verify-modules` 使用固定合成源码与真实隔离 Docker / Chromium，检查第二模块在点击前未被请求、模拟状态跨模块共享与保留、仅重建一个模块，以及导出源码能由 Vite 重新构建。它不调用模型。

## 2026-11-13 本机结果

Node 24.22.1、macOS arm64、本机 PostgreSQL 16 和回环 HTTP；响应体为 JSON 字节，初次读取不含浏览器渲染耗时。1000 张需求对应 10 万条消息、200 份长材料、50 个模块。

| 测量 | 结果 |
| --- | --- |
| 完整项目 / 紧凑首屏 | 47.67 MB / 4.05 MB，减少 91.5% |
| 紧凑首屏服务请求 | 97ms |
| 20 并发，持续读取 30 秒 | 129345 次；无变化响应 68 字节；P95 6.59ms |
| 512 次发言，4 并发写入 | P95 52.29ms；无冲突、无丢失 |
| 写入期间的增量读取 | 3033 次；P95 18.20ms；无快照回退 |
| 单次追加后的增量 | 8797 字节，9.06ms，重建结果一致 |
| 模块失效规划 | 50 个模块只变 1 个，传入 20 张需求而非 1000 张；不调用模型 |
| 真实模型两个模块并行生成 | 53.62 秒，通过隔离交互检查 |
| 真实模型只改一个模块 | 23.30 秒；另一模块的产物 ID 与源码摘要保持 |

100 / 300 / 1000 张需求的默认压测全部通过预算。原始结果位于本地忽略目录 `.work/scaling/load-test.json`、`load-test-sustained.json`、`modular-runner/modular-report.json` 和 `live-verification.json`。以上是本机短时负载与真实合成流程的验收结果，不代表外网部署、企业多实例或长时间容量上限；模型生成耗时仍受网关和模型影响。

## 共享业务数据补充

`server/demo-business-contract.ts` 根据有效需求生成统一业务数据定义，复用同一输入的规划结果。模块通过 `useBusinessState` 读取和原子更新单据、审批、收货与库存等关联数据。该定义对模块生成阶段只读；业务规则调整但接口不变时可原样复用，接口改变时模块缓存失效。概要全部字段同时参与项目与模块更新判断。
